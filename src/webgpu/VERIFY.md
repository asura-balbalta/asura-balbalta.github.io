# 렌더링 변경의 확인·검증·수정 절차

`src/webgpu/` 아래(렌더러·셰이더·후처리·카메라)를 고치거나 기능을 더한 뒤 따르는 절차. 2026-10-14 SSAO 가로 줄무늬를 잡으며 효과가 있었던 순서를 정리한 것이다(원인·경과는 `docs/design-code-plan.md` 6절 10차 수정 4).

## 0. 원칙

- **추정으로 고치지 않는다.** 증상을 먼저 재현하고, 범위를 좁히고, 수치로 확인한 뒤 고친다. 추정이 두 번 틀리면 재현부터 다시 한다.
- 증상을 보고한 조건(화면 크기·자리·각도·URL 파라미터)을 **그대로 맞춘다.** 비교 캡처는 같은 자리·같은 각도에서만 유효하다.
- 바뀐 코드와 바뀐 증상을 **되짚는다.** "이번 라운드에 무엇을 바꿨나" 목록에서 회귀 후보를 먼저 본다.

## 1. 빌드와 미리보기

```bash
npm run typecheck   # tsc --noEmit. 타입 오류의 기준(에디터 진단은 믿지 않는다)
npm run build       # esbuild → dist/. 미리보기 전에 반드시
```

- 미리보기는 `.claude/launch.json` 의 `dist-static`(`npx serve dist`, 3000 포트). 다른 서버를 쓰지 않는다. `npm run dev`(watch)는 사용자가 직접 돌린다. 돌고 있으면 빌드를 생략한다.
- WGSL 오류는 타입 검사에 안 잡힌다. 빌드 뒤 페이지를 열어 **콘솔 오류**를 본다.

## 2. 내장 브라우저로 확인할 때

- 둘러보기(게임 모드)는 `?lock=0` 으로 들어간다. 포인터 잠금이 내장 브라우저에서 실패해 포커스가 없으면 합성 마우스·키 이벤트가 무시된다.
- 진입은 `find` 로 "둘러보기" 요소를 찾아 클릭. 시점·이동은 합성 이벤트로:
  `document.dispatchEvent(new MouseEvent('mousemove', {movementX, movementY}))`, `new KeyboardEvent('keydown', {code: 'KeyW'})` + `keyup`.
- 상태 표시줄 "프레임 n ms" 는 판이 보일 때 값만 믿는다(숨겨지면 1000 ms).
- **캡처의 한계**: 내장 브라우저 캡처는 2배 캔버스를 1배 이하로 줄인 JPEG 라 미세한 띠·점·1 px 선이 묻힌다. 캔버스 픽셀은 JS 로 읽을 수 없다(WebGPU 캔버스는 표시 뒤 읽기 불가). 미세 품질은 3절의 디버그 출력으로 보거나 사용자의 Chrome 캡처로 판단한다.
- **뷰포트 에뮬레이션의 한계**: `resize_window` 1024×768 은 판 크기(예: 878×946)와 달라 **크기에 민감한 증상은 재현이 안 될 수 있다.** 사용자가 본 증상은 먼저 에뮬레이션을 끄고(preset desktop) 같은 크기에서 재현한다. 둘러보기 중에 크기만 바꾸면 재진입 없이 크기 의존성을 훑을 수 있다.
- 확인이 끝나면 뷰포트를 desktop 으로 되돌린다.

## 3. 증상이 보고되면: 재현 → 좁히기 → 수치 → 수정

1. **재현.** 사용자의 조건(주소·범위·자리·각도·크기·URL)을 맞춰 같은 증상을 본다. 안 보이면 조건이 다른 것이다. 크기·자리·각도를 하나씩 맞춰 본다.
2. **효과 끄기로 범위 좁히기.** 같은 자리에서 URL 파라미터를 하나씩 바꿔 어느 pass 에서 나는지 가른다(아래 표). 캡처는 반드시 같은 자리·각도.
3. **디버그 출력으로 수치 확인.** 캡처로 판단이 안 되면 합성 pass 에 **실행 중 바꿀 수 있는 스위치**(`window.__xxx`, uniform 한 칸)를 임시로 넣어 중간값을 화면에 그대로 내보낸다. 예: 흐림 전·후 AO(대비 8배), 복원 법선(n·0.5+0.5), 거리 등고선(fract(d/0.25)), 이웃 픽셀과의 거리 차(×10), 같은 계산의 전해상도 버전, 해상도 배율 스위치. 흰색 = 0 으로 두면 판독이 쉽다. 새로고침 없이 모드를 바꿔 가며 찍는다.
4. **파라미터 흔들기.** 같은 스위치로 bias·반지름·세기 같은 값을 실행 중에 바꿔 증상이 어느 항에 반응하는지 본다.
5. **회귀 되짚기.** 이번 라운드에 바꾼 줄 목록에서 증상과 맞는 것을 찾는다. "전에는 틀렸지만 일관됐고, 고친 뒤 일관성이 깨진" 경우가 흔하다.
6. **수정 → 1·2 재확인 → 디버그 코드 제거 → 빌드 → 콘솔 오류 없음 확인.**
7. **기록.** `docs/design-code-plan.md` 해당 절에 원인·수정·확인을 한 줄로. 커밋은 `fix(render): …` 에 원인/수정/검증/재발 방지 본문.

## 4. 효과별 URL 파라미터(둘러보기)

| 파라미터 | 효과 |
| --- | --- |
| `?lock=0` | 포인터 잠금 없이 흉내(내장 브라우저 확인용) |
| `?ao=0` | SSAO 끄기 |
| `?shadow=0` | 그림자 끄기 |
| `?sky=0` | 절차적 하늘 끄기(안개는 배경색으로) |
| `?edge=0.25` | 외곽선 세기(0 이면 끄기) |
| `?sun=60` | 하늘 태양 고도(°, 테마 값 대신) |

새 효과를 더하면 끄는 파라미터도 같이 둔다. 감각이 갈리는 값은 파라미터나 조절 패널로 두 경로를 함께 두고 사용자가 Chrome 에서 비교한 뒤 기본값으로 옮긴다.

## 5. 후처리 pass 를 쓸 때의 규칙

- **깊이에서 위치를 복원**할 때는 카메라를 원점에 둔 행렬(`camera.ts` `cameraViewProjRelative`)을 쓴다. 월드 좌표를 f32 로 복원하면 0.1 ~ 0.5 mm 오차가 남는다.
- **반해상도 pass** 는 깊이 픽셀 번호를 정수로 구해(`floor(fragPos × 깊이크기/pass크기)`) 그 픽셀 **중심** uv 로 복원한다. 픽셀 경계에 걸린 uv 를 `floor(uv × 크기)` 하면 f32 오차로 행마다 갈려 줄무늬가 난다. 이웃·표본 조회도 조회한 픽셀 중심으로 통일한다(`ao.ts` `worldAtPixel`).
- 깊이 비교 여유(bias)는 거리에 비례시킨다. 비스듬한 면은 한 픽셀이 수 cm ~ 수십 cm 다.
- 구간을 나누는 효과(캐스케이드)는 경계에 섞는 띠를 처음부터 둔다. 격자 기반 효과는 격자를 세계에 고정한다.
- 깊이는 역순 depth32float(0 = 가장 멂). 전체 화면 pass 가 "장면이 안 그린 픽셀" 만 칠하려면 z = 0 에 `depthCompare: "equal"`, 깊이 첨부는 읽기 전용.
